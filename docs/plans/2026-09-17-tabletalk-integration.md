# Plan — table-talk ⇄ buildboard integration (buildboard canonical)

**Date:** 2026-09-17 · **Status:** in progress · **Repos:** `buildboard` (canonical, local) + `table-talk` (→ `/home/gnava/repos/table-talk`)

## Goal

Make a **decision one object reachable from three surfaces** — chat (by short `ref`), the board (card + its thread), and any agent (MCP) — so chat and decision-making stop being two systems. Three bridges (decision, glossary, task) are the same pattern, instantiated per record type.

## Confirmed decisions

1. **Board-only in board mode** — when `BUILDBOARD_URL` is set, the table-talk CLI writes *only* to buildboard; JSONL writes are disabled (explicit `--local` to opt back in). No silent fallback.
2. **buildboard generates `ref`** — single source of IDs. CLI/agents relay the returned `ref`.
3. **table-talk checked out at `/home/gnava/repos/table-talk`.**

## Architecture

| table-talk | buildboard (canonical) | mapping |
|---|---|---|
| `action` (open) | `item(kind=decision)` + `decisions` row, `choice=NULL` | ask→question, options→options, why→rationale-context, rec→recommended option |
| `action` (done) | `decisions.choice` set (status stays `active`) | answering closes it everywhere |
| `term` | `concepts` row (dedup by name) | intuitive→definition, technical→details_md |
| `task` | `item(kind=task)` (+`agent_task`) | what→title/body, progress→body_md, `--pct`→`items.pct` |
| `task --blocked-on <ref>` | `edge(kind='blocks')` + `status='blocked'` | clears when the decision resolves |
| (none) | `thread`/`messages` on the item | the durable discussion |

`ref` = 4-hex, generated by buildboard (`crypto.randomBytes(2)`), **globally unique** across items/decisions/concepts, collision-retry, backfilled on existing rows. Resolved by `resolveRef(ref)` in order items → decisions → concepts.

## The unifying thread

> **One record · three surfaces · one loop · one handle.**
> - **One record:** each table-talk event is a *single canonical buildboard row* (decision / concept / item) — never scattered writes.
> - **Three surfaces:** chat (by `ref`), board (card + thread), and any agent (MCP) all address that same row.
> - **One loop:** propose → surface (brief + board) → discuss (thread) → **answer/advance via one side-effecting primitive** → unblock → resurface.
> - **One handle:** a buildboard-generated `ref`, echoed everywhere, resolved by one `resolveRef(ref)`.

Side-effects live in **exactly one store function per transition**, so chat / board / agent can never drift. Phase 0 builds those primitives; Phases 1–3 are thin clients over them.

## Phase 0 — Foundations (buildboard) ⭐ the linchpin

**Goal:** `ref` + the side-effecting primitives + unblock + MCP. Everything else is a client over this.

- **Schema:** `ref TEXT` + `CREATE UNIQUE INDEX` on `items`, `decisions`, `concepts`; backfill existing rows in one appended `MIGRATIONS` entry. `newRef()` in `db.ts` next to `newId()`; cross-table pre-check + bounded retry. `types.ts`: add `ref?`.
- **Primitives (store.ts):**
  - `recordDecision({question, options, why, rec, ref, board_id})` → item(`kind=decision`) + decision row + seeded thread (system msg = question) + returns `{ref, item, decision}`. Fixes the orphan-invisible trap (brief joins through items).
  - `resolveDecision(ref, answer)` → **one transaction**: normalize answer (case-insens. option match → `N`/`option N` → free-text if no options), set `choice`, post answer to thread with `meta={ref,decision_id}` (idempotent: same ref+choice = no-op), flip decision item `status=done`, **unblock** items with outgoing `blocks` edges. Returns updated decision **and** item + unblocked list.
  - `unblock(itemId)` helper (atomic; the `blocks` edge → status flip).
- **REST:** `GET /api/ref/:ref`; accept/return `ref` on decisions/concepts/items; `?ref=` filters.
- **MCP:** `bb_decide` (compound create), `bb_decision_resolve(ref, choice, rationale?)`, `bb_decision_get`; accept `ref` on `bb_decision_update`; **`bb_brief`** active-decisions lines become `- [a3f9] question — options: A, B (blocks: 1) (answer: bb_decision_resolve)`.
- **Tests:** vitest for ref CRUD, `resolveRef`, `recordDecision`, `resolveDecision` (thread post + idempotency + unblock); MCP tool tests; migration-upgrade test.

## Phase 1 — Decision bridge (CLI board mode + UI)

- **table-talk CLI board mode:** resolve `BUILDBOARD_URL`(+`BUILDBOARD_BOARD`) → one client; board-only (single JSONL guard); **fail fast** if unreachable (distinct "not running" vs "wrong URL" via `/api/health` probe); `action`→`bb_decide`, `done <ref> [--choice N]`→`bb_decision_resolve`, `show --open`→board open items (ref column); idempotency (done idempotent; create dedup via same-title search + ~5-min grace); `--dry-run`/`--json`; print `ref` + deep-link.
- **Deep links (buildboard):** `?board=<id>&item=<ref|id>` parsed at load (prereq for clickable card URLs).
- **UI:** decision card shows mono `ref` chip + open/resolved glyph + **inline clickable option chips** (resolve in place, toast, no detail-panel trip).
- **Tests:** CLI integration (record→assert DB→done→resolved+unblocked); e2e full loop (propose→board card→answer by ref→card updates→blocked task opens).

## Phase 2 — Glossary bridge

- **store:** `upsertConceptByName(normalizedName, {definition, details_md, ref})` — atomic, removes the `duplicate` error path; normalized key (trim + casefold).
- **CLI:** `term`→upsert; **board loads concepts** alongside items; concept card renders `definition` (line 1) + truncated `details_md` (line 2).
- **brief:** include board-independent glossary (top N) so detached terms are visible.
- **Tests:** upsert dedup / casefold; CLI term round-trip; card render.

## Phase 3 — Task bridge

- **Schema:** `ALTER TABLE items ADD COLUMN pct REAL` (fallback: `tags` `pct:N`).
- **CLI:** `task`→`recordTask` (item kind=task, canonical `[tt] <what>` title); `progress <ref> "..." --pct N`→update body/pct (idempotent vs last thread msg); `--blocked-on <action-ref>`→`blocks` edge + `status=blocked` (catch the `(from,to,kind)` 409); `done`→`status=done`.
- **Agent link:** `bb_spawn_agent(item_id)` on the task item; **close runner gaps** — sync item status on finalize (`in_progress`→`done`/`blocked`), and throttle-append transcript to `body_md` so the card preview shows live progress.
- **UI:** `NN%` chip on the card; `pct=100`→`status=done` server-side (in `updateItem`).
- **Tests:** pct round-trip; block→resolve→unblock; runner status sync.

## Phase 4 — Live board + polish

- **Board SSE (enabler):** board/global event endpoint (precedent: `agent-tasks/[id]/events`); `Board.svelte` subscribes + diff-refreshes nodes/edges; fallback 5–10s poll. Makes agent writes visible without reload.
- **Edge/status visual language:** per-kind edge styles (`blocks`=dashed/amber + auto label, default from decision items; `depends_on`=solid); style the currently-dead `.st-*` status glyphs with tokens; decision-state tokens (open/resolved/superseded).
- **Closed loop:** "⊘ waiting on #a3f9" footer on blocked cards → click focuses the decision (reuse `focusItem`+`setCenter`); on resolve, surface a one-click unblock toast. Thread liveness + timestamps + unread badge.
- **Docs:** update both READMEs + a `docs/` protocol page.

## Cross-cutting QoL (folded above)

- Side-effects in **exactly one store function per transition** (chat/board/agent can't drift).
- `ref` echoed in card chip, detail header, brief, search hits, MCP returns; `get*` accept `ref`.
- MCP: consistent `ref` param naming; merge `bb_item_update` into `bb_item_upsert`; `bb_item_get(with_context)`; `bb_messages` cursor pagination.
- Supersede vs resolve: `superseded` stays "abandoned/replaced" with `superseded_by` ref; never a resolve path.

## Acceptance criteria

- A decision proposed in chat, on the board, and by an agent is the **same row** with the **same `ref`**.
- Answering by `ref` (CLI/chat) **or** clicking an option (board) **or** `bb_decision_resolve` (agent) → choice set, answer in thread, blocked items unblock, card updates **live**.
- `bb_brief` lists unresolved decisions with `ref` + options so any agent can act.
- Glossary and tasks behave identically (one record, three surfaces).
- Full gate green on buildboard; CLI board-mode tests pass against a buildboard test instance.

## Risks / open

- 4-hex space (~65k) → collisions become likely past ~100–200 rows; mitigated by cross-table unique index + retry (5-hex is a drop-in later).
- Board SSE is the biggest UI chunk; if it slips, ship with the 5–10s poll fallback.
- Two repos / two test harnesses (vitest + shell/pytest); table-talk must be cloned first.
- Dev-server/DB-lock: run buildboard test instance on a spare port + temp DB.
